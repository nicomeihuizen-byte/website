~/how we ship

Vite, sans lâcher les freins.

La vitesse de l’IA ne vaut quelque chose que si le processus rattrape ce que l’IA fait de travers. Chaque modification suit donc le même chemin, qu’il s’agisse d’une coquille ou d’un nouvel agent. Pas d’exception pour les « petites ».

● pipeline · branch → main✓ tous les contrôles réussis · déployé
  1. branchChaque modification sur sa propre branche. Main n’est jamais modifiée directement.
  2. pull requestDécrite, reliée à sa raison d’être, lisible un an plus tard.
  3. ci: scan + testsScan de sécurité CodeQL et tests unitaires à chaque push et chaque pull request.
  4. ci: evalsFritz répond à ses questions pièges à chaque déploiement de preview. Rouge, pas de merge.
  5. human reviewNico lit le diff. Rien n’est mergé sans avoir été lu.
  6. cd: deployLe merge sur main suffit à livrer. Aucun fichier copié à la main.
  7. monitorPage de statut publique. Si quelque chose casse, vous le voyez aussi.

CodeQL · ce sitenpm test · agent-fritz-guardrails, à chaque pushFritz evals · à chaque déploiement VercelESLint + Next.js build · Fivediagnostic du site · contrôle SEO et sécurité

git
Tout sous contrôle de version

Code, prompts, évaluations et textes du site. Si ce n’est pas dans Git, ça n’existe pas.

ci/cd
Contrôles au vert, sinon pas de mise en production

Un contrôle rouge sur une preview, et rien n’est mergé. Personne ne passe outre pour tenir une échéance.

evals
Les agents sont testés comme du code

Une série fixe de questions pièges que chaque agent doit réussir avant qu’une modification parte.

secrets
Les clés ne touchent jamais le dépôt

Les identifiants vivent dans les paramètres de la plateforme d’hébergement, par environnement.

gdpr
Données UE, par écrit

Une page de confidentialité qui dit ce qui est conservé, combien de temps, et à qui demander la suppression.

open
La preuve en public

Les garde-fous et le banc de test de Fritz sont dans un dépôt public. Lisez les tests vous-même.

~/how I work with AI

Un outil. Un très bon outil.

  1. 01
    C’est un outil, pas le travailUn modèle seul ne produit rien qu’un client puisse utiliser. Le résultat vient du workflow qui l’entoure.
  2. 02
    Les pipelines battent les promptsUn prompt isolé est un pari. Des entrées maîtrisées et des étapes reproductibles sont une méthode de production.
  3. 03
    Par défaut, le résultat est un brouillonIl part quand il survit à la relecture, pas quand il compile.
  4. 04
    Savoir où ça casseChaque modèle échoue quelque part. Savoir où décide si l’IA est seulement le bon outil.
  5. 05
    Le modèle ne décide pas de ce qui est bonIl élargit ce qu’une personne peut construire. Le jugement reste humain.
