One Acre, Zero Dependency.

Off-grid, AI-driven farming on two plots 2,256 km apart: Prora through summer, Castelo Branco through winter. One question: how much of a small farm's daily decisions can genuinely off-grid AI handle, from sensor to scheduler?

Open the repo → Project brief (PDF)

Two plots, one season

Prora runs through the summer, Castelo Branco through the winter. Between them there is never a month with nothing growing.

Nothing leaves the acre

Sun to sensor to laptop to schedule. The model runs locally, which is the only way the off-grid claim survives contact with a bill.

The model proposes, Python disposes

Every suggestion passes a deterministic rule set before it becomes a task. What fails the rules is dropped, and the drop is logged.

~/what it does

Sensor, history, calendar, model.

A solar-powered field module (Birdbox) collects soil and local weather data. The Open-Meteo historical archive adds twenty years of regional weather. Eurostat adds regional yield figures, coarse ones: annual, per hectare, per region, not per bed. The Thun calendar supplies a moon-based planting calendar, which this project computes correctly and tests instead of assuming.

The calculations run in Python. A local model lays the results side by side and proposes which crops give the best yield per planting, when to sow, and which rotations work on 4,000 m².

The aim: something farmers, hobby growers and families can hold on to, to grow organically at any scale, on modern technique and age-old concepts that protect the earth.

~/commitments

Three things it does not compromise on.

01

Off-grid means off-grid.

No cloud LLM in the daily loop.

02

Every number carries its error bars.

A €30 sensor claiming ±0.3 pH does not get to report pH to one decimal.

03

The calendar is a hypothesis.

The biodynamic calendar is under test, not a scheduling rule.

~/the calendar

The Thun calendar, honestly implemented.

The evidence does not support the trigon effect. The calendar is therefore logged as a covariate and tested, never used as a rule.

~/models

The LLM proposes, Python disposes.

Every number is computed in tested Python. The model selects, prioritises and explains, and returns JSON validated against a schema. What fails the rules is dropped, and the drop is logged. What it is aimed at: yield per square metre.
