~/how we ship

Veloci, ma con i freni.

La velocità dell’AI vale qualcosa solo se il processo intercetta ciò che l’AI sbaglia. Per questo ogni modifica segue lo stesso percorso, che sia un refuso o un nuovo agente. Nessuna eccezione per quelle “piccole”.

● pipeline · branch → main✓ tutti i controlli superati · in produzione
  1. branchOgni modifica sul suo branch. Main non si modifica mai direttamente.
  2. pull requestDescritta, collegata al perché, leggibile un anno dopo.
  3. ci: scan + testsScansione di sicurezza CodeQL e unit test a ogni push e pull request.
  4. ci: evalsFritz risponde alle sue domande trabocchetto a ogni deploy di anteprima. Rosso significa niente merge.
  5. human reviewNico legge il diff. Niente viene unito senza essere letto.
  6. cd: deployIl merge su main lo mette in produzione. Nessun file copiato a mano.
  7. monitorPagina di stato pubblica. Se si rompe, lo vedi anche tu.

CodeQL · questo sitonpm test · agent-fritz-guardrails, a ogni pushFritz evals · a ogni deploy VercelESLint + build Next.js · Fivediagnostica del sito · controllo SEO e sicurezza

git
Tutto sotto controllo di versione

Codice, prompt, eval e testi del sito. Se non è in Git, non esiste.

ci/cd
Controlli verdi o niente rilascio

Un controllo rosso su un’anteprima significa niente merge. Nessuno lo scavalca per rispettare una scadenza.

evals
Gli agenti si testano come il codice

Una serie fissa di domande trabocchetto che ogni agente deve superare prima che una modifica esca.

secrets
Le chiavi non toccano mai il repo

Le credenziali stanno nelle impostazioni della piattaforma di hosting, per ambiente.

gdpr
Dati UE, messi per iscritto

Una pagina privacy che dice cosa viene conservato, per quanto tempo e a chi chiedere di cancellarlo.

open
Prove in pubblico

I guardrail e il test harness di Fritz sono un repo pubblico. Leggi i test tu stesso.

~/how I work with AI

Uno strumento. Ottimo, ma uno strumento.

  1. 01
    È uno strumento, non il lavoroUn modello da solo non produce nulla che un cliente possa usare. Il risultato viene dal flusso di lavoro che gli sta intorno.
  2. 02
    Le pipeline battono i promptUn prompt è una scommessa. Input controllati e passaggi ripetibili sono un metodo di produzione.
  3. 03
    L’output di base è una bozzaVa in produzione quando supera la revisione, non quando compila.
  4. 04
    Sapere dove si rompeOgni modello sbaglia da qualche parte. Sapere dove decide se l’AI sia lo strumento giusto.
  5. 05
    Non è il modello a decidere cosa valeAmplia ciò che una persona può costruire. Il giudizio resta umano.
