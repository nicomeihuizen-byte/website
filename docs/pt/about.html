~/how we ship

Rápido, mas com os travões ligados.

A velocidade da IA só vale alguma coisa se o processo apanhar o que a IA faz mal. Por isso, cada alteração segue o mesmo caminho, seja uma gralha ou um novo agente. Sem exceções para as "pequenas".

● pipeline · branch → main✓ todas as verificações aprovadas · implementado
  1. branchCada alteração no seu próprio branch. O main nunca é editado diretamente.
  2. pull requestDescrito, ligado ao porquê, legível um ano depois.
  3. ci: scan + testsAnálise de segurança CodeQL e testes unitários em cada push e pull request.
  4. ci: evalsO Fritz responde às suas perguntas-armadilha em cada deploy de pré-visualização. Vermelho significa que não há merge.
  5. revisão humanaO Nico lê o diff. Nada entra sem ser lido.
  6. cd: deployO merge para o main põe em produção. Sem ficheiros copiados à mão.
  7. monitorPágina de estado pública. Se algo falhar, também o vê.

CodeQL · este sitenpm test · agent-fritz-guardrails, cada pushFritz evals · cada deploy na VercelESLint + Next.js build · Fivediagnóstico do site · revisão de SEO e segurança

git
Tudo sob controlo de versões

Código, prompts, evals e textos do site. Se não está no Git, não existe.

ci/cd
Verificações verdes ou não há lançamento

Uma verificação vermelha numa pré-visualização significa que não há merge. Ninguém a contorna para cumprir um prazo.

evals
Os agentes são testados como código

Um conjunto fixo de perguntas-armadilha que cada agente tem de passar antes de uma alteração sair.

secrets
As chaves nunca tocam no repositório

As credenciais ficam nas definições da plataforma de alojamento, por ambiente.

gdpr
Dados na UE, por escrito

Uma página de privacidade que diz o que é guardado, durante quanto tempo e a quem pedir para o apagar.

open
Provas em público

As salvaguardas e o ambiente de testes do Fritz estão num repositório público. Leia os testes.

~/how I work with AI

Uma ferramenta. Muito boa.

  1. 01
    É uma ferramenta, não o trabalhoUm modelo sozinho não produz nada que um cliente possa usar. O resultado vem do fluxo de trabalho à sua volta.
  2. 02
    Pipelines valem mais do que promptsUm prompt é uma aposta. Entradas controladas e passos repetíveis são um método de produção.
  3. 03
    O resultado por defeito é um rascunhoVai para produção quando sobrevive à revisão, não quando compila.
  4. 04
    Saber onde falhaTodos os modelos falham algures. Saber onde decide se a IA é sequer a ferramenta certa.
  5. 05
    Não é o modelo que decide o que prestaAlarga o que uma pessoa consegue construir. O critério continua a ser humano.
