~/how we ship

Schnell, und die Bremsen funktionieren noch.

Tempo durch KI ist nur etwas wert, wenn der Prozess abfängt, was die KI falsch macht. Deshalb nimmt jede Änderung denselben Weg, ob Tippfehler oder neuer Agent. Keine Ausnahmen für „kleine“.

● pipeline · branch → main✓ alle Checks bestanden · deployt
  1. branchJede Änderung auf einem eigenen Branch. Main wird nie direkt bearbeitet.
  2. pull requestBeschrieben, mit dem Warum verknüpft, auch in einem Jahr noch lesbar.
  3. ci: scan + testsCodeQL-Sicherheitsscan und Unit-Tests bei jedem Push und Pull Request.
  4. ci: evalsFritz beantwortet bei jedem Preview-Deploy seine Fangfragen. Rot heißt: kein Merge.
  5. human reviewNico liest den Diff. Nichts wird ungelesen gemergt.
  6. cd: deployDer Merge auf Main liefert aus. Keine von Hand kopierten Dateien.
  7. monitorÖffentliche Statusseite. Wenn etwas kaputtgeht, sehen Sie es auch.

CodeQL · diese Websitenpm test · agent-fritz-guardrails, bei jedem PushFritz evals · bei jedem Vercel-DeployESLint + Next.js build · FiveWebsite-Diagnose · SEO- und Sicherheitsprüfung

git
Alles in der Versionskontrolle

Code, Prompts, Evals und Website-Texte. Was nicht in Git ist, existiert nicht.

ci/cd
Grüne Checks oder kein Release

Ein roter Check in einer Preview heißt: kein Merge. Niemand übergeht ihn, um eine Deadline zu halten.

evals
Agenten werden getestet wie Code

Ein fester Satz Fangfragen, den jeder Agent bestehen muss, bevor eine Änderung rausgeht.

secrets
Schlüssel kommen nie ins Repo

Zugangsdaten liegen in den Einstellungen der Hosting-Plattform, pro Umgebung.

gdpr
EU-Daten, schriftlich festgehalten

Eine Datenschutzseite, die sagt, was gespeichert wird, wie lange, und wen Sie um die Löschung bitten.

open
Belege, öffentlich

Die Guardrails und das Test-Harness von Fritz sind ein öffentliches Repo. Lesen Sie die Tests selbst.
